# Этап 1 — реализация и приёмка

Исходная база: `8e32d3d` (0.6.22). Реализация этапа 1 была собрана как 0.6.23; исправления по `STAGE1-VALIDATION.md` входят в **0.6.24**. Все изменения остаются в текущей ветке без коммита.

## Поведение

| Пункт | Реализация |
|---|---|
| C1 | Разрешённый ввод отправляется до медиа-работы после проверки намерений меню/stop, транспорта, поколения и запретов. Отпускания клавиш переживают запрет видео и отказ очереди. |
| C2 | Радиальная мёртвая зона геймпада 4%; курсор сохраняет прежние 12% по оси. |
| S5 | Настройки сохраняет один фоновый writer: debounce 500 мс, последние значения по ключам, завершения в UI, flush/join при выходе. Rental/auth durability не изменена. |
| P9 | Снимки Media раз в секунду, fsync/commit RunLog раз в 5 с, подробные дампы раз в 15 с. Короткие метрики задержек, LoopTiming и Playback timing всегда выводятся и сбрасываются раз в 5 с. |
| P10 | Загрузка обложек/Steam lookup приостанавливается во время сессии, отменённые запросы возвращаются в очередь. |
| S14 | Приостановка ввода при core/local IDR wait или отсутствии кадра 150 мс отделена от прежнего ожидания ключевого кадра. Не меняет баннер и непрерывность метрики показа. Причины, число входов и длительности записываются отдельно. |
| S2/S11 | После подтверждённого запуска повторяется только классифицированная транспортная ошибка. Поздний GS_OK сохраняет идентичность и открывает отдельные 15 с транспорта; ручная отмена побеждает. |
| S9/S10 | Общий AU 8 МиБ. Повтор IDR без RTP ограничен ожиданием, которое открыла локальная команда декодера. Другие core/network ожидания сохраняют прежние повторы по кадрам. |
| P4 | С 0.6.27 MTS догоняет при очереди ≥3 либо ≥2, если старший кадр ждёт не меньше двух кадровых интервалов: 34 мс для 60 FPS, 67 мс для 30 FPS. До 2–3 AU с FIFO и бюджетом 12 мс. Свежая пара получает отдельные проходы показа. |
| S16 | Общая политика PCM доступна экспериментально; обычная сборка сохраняет прежний синхронный звук до внешнего A/V-замера. |

Диагностика Moonlight теперь подключена в composition к настоящему RunLog. Её исправление и защитные изменения S2/S11/S9, поколения ввода и key-up включены во всех сравнительных сборках.

Подробности: [исправления валидации](STAGE1_VALIDATION_FIXES.md), [политика Moonlight](STAGE1_MOONLIGHT_POLICY.md).

## Независимые варианты A/B

Контрольный профиль — общая исправленная база, **не побайтовая 0.6.22**. Меняется только указанная группа поведения; исправленная диагностика и защитные проверки остаются одинаковыми.

| STAGE1_PROFILE | Изменение относительно control |
|---|---|
| control | Поздний ввод, прежний порог догона, осевая зона 12%, синхронные настройки, прежняя частота диагностики, работа обложек, без дополнительного S14 и локального IDR-таймера |
| c1 | Только ранняя отправка ввода |
| c2 | Только радиальная зона геймпада 4% |
| s5 | Только фоновое сохранение настроек |
| p9 | Только сокращение частоты подробной диагностики, публикации снимков и sync RunLog; метрики остаются по 5 с |
| p10 | Только пауза обложек |
| s14 | Только дополнительная приостановка ввода |
| s10 | Только повтор IDR для локальной ошибки декодера |
| p4_legacy | Только прежний P4 из 0.6.24–0.6.26: догон любой очереди ≥2, для воспроизведения регрессии |
| p4 | Только исправленный P4 с возрастным порогом из 0.6.27 |
| s16 | Только общая ограниченная политика PCM в синхронном пути |
| full | Все группы, кроме S16; обычная сборка |

```sh
STAGE1_PROFILE=control bash build.sh
STAGE1_PROFILE=c1 bash build.sh
# Все варианты одной неизменной базы; последний всегда full:
python3 tools/build-stage1-variants.py --output /path/to/new/experiment-directory
# Сравнение только политики догона на общей текущей базе (+ full в конце):
python3 tools/build-stage1-variants.py --profiles control p4_legacy p4 --output /path/to/new/p4-comparison
```

Скрипт отказывается заменять существующие варианты. `matrix.json` и `experiment.json` фиксируют профиль, SHA-256 NRO/ZIP, исходники/ресурсы и fingerprint зависимостей. `build-inputs.json` содержит хеши компилятора, SDK, заголовков и установленных библиотек. Изменение любого входа между сборками прекращает создание матрицы. `Stage1 options` в runtime-логе показывает реально включённые группы, включая `mts_catchup_age_guard`. У p4 и p4_legacy одинаковая маска 128, но различается этот флаг; он также записан в manifest. Старые архивы 0.6.24 не изменены: их p4 соответствует нынешнему p4_legacy по политике догона, но не по всей кодовой базе.

Для старого способа включения звука сохраняется `BOUNDED_SYNC_AUDIO=1 bash build.sh`; при изготовлении матрицы независимый s16 выбирается исключительно профилем. Нельзя приписывать результат `full` одной конкретной оптимизации.

## Аппаратная приёмка остаётся открытой

Нужны FH-прогон с ожиданием IDR и цепочкой в сыром логе/анализаторе, A/B по одной группе на одной сцене, оба провайдера, H.264/H.265 и 30/60 fps. Проверить menu/focus/stop, прерывание и восстановление ввода, серию запусков/остановок, звук и AUTO. Частоту нейтрализаций S14 оценивать по `Input suspension`; core/local/noFrame могут перекрываться, их длительности нельзя суммировать.

S16 нельзя включать по умолчанию до внешнего A/V-замера. Размер SDL-очереди не показывает рассинхрон. При аварийном отключении питания обычная диагностика full/P9 может потерять примерно последние 5 с; журналы аренды/авторизации сохраняют прежний контракт.
