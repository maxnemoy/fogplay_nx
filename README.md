# FogPlay NX

Неофициальный клиент облачного гейминга **МТС Fog Play** для Nintendo Switch с Atmosphère.

> [!CAUTION]
> **Проект не имеет никакого отношения к компании МТС, не разрабатывается и не поддерживается ею.** Для использования нужен аккаунт Fog Play. Аренда удалённых компьютеров оплачивается по условиям сервиса. Названия сервисов, логотипы и обложки игр принадлежат их правообладателям. 
>
> **Для привязки способов оплаты используйте только [официальные клиенты](https://fogplay.mts.ru/)**
>
> Проект экспериментальный. При обнаружении проблем, вылетов или лагов открывайте issue и прикрепляйте `/switch/fogplay_nx/last-run.log` либо файлы из `/switch/fogplay_nx/logs/` на SD-карте. Не прикладывайте всю папку `/switch/fogplay_nx/`: в ней также хранятся данные авторизации.


## Возможности

- Каталог, поиск, фильтр жанров, подгрузка игр и пять последних запусков.
- Выбор компьютера с измерением сетевой задержки, вход и сохранение авторизации на SD.
- Создание и завершение игровой сессии, видео H.264/H.265, звук и геймпад.
- Мышь стиком или сенсором, экранная клавиатура с отправкой текста на удалённый ПК.
- Настройки качества, битрейта, ключевых кадров и раскладки Xbox.
- Обложки МТС с резервным поиском в Steam и кэшированием на SD.

H.265 используется только при совместимом предложении сервера. Запрошенный битрейт — ограничение/пожелание серверу, а не гарантия скорости потока.

## Запуск на Switch

1. Скопируйте содержимое `fogplay_nx-sd.zip` в корень SD-карты.
2. Откройте hbmenu в полном режиме приложения: удерживайте **R** при запуске установленной игры. Запуск через Album не поддерживается.
3. Запустите FogPlay NX, войдите в аккаунт, играйте.

Во время трансляции удерживайте **−** и нажмите **+**: откроется меню мыши, клавиатуры, изображения и завершения сессии. Закрытие этого меню продолжает игру.

Для окончания аренды выберите **«Завершить сессию»** и дождитесь подтверждения. Клиент также пытается остановить аренду при выходе в HOME и невосстановимой ошибке. При аварии или потере сети подтверждение может не прийти: проверьте активную аренду в официальном клиенте Fog Play. Локальный журнал восстановления сохраняется до разрешения ситуации.

Вход, настройки, кэш и журналы хранятся в `/switch/fogplay_nx/` независимо от папки установленной версии. Не публикуйте содержимое этой папки: файлы авторизации дают доступ к аккаунту. Перед копированием журналов через DBI полностью закройте приложение.

При запуске сначала появляется стартовый экран. В журнал записывается длительность этапов от входа в приложение до первого кадра интерфейса; время загрузчика до входа в приложение туда не входит. История журналов сохраняется без повторного копирования уже архивированных запусков.

В разделе PlayStation карточки обновляются по мере ответов МТС. Пока запросы выполняются, сверху отображается «Обновление серверов…». Подключение доступно после завершения проверки списка.

## Окружение для сборки

Сборка выполняется в **Linux x86_64** или **WSL2 Ubuntu**. В Windows храните исходники в файловой системе WSL (например, `~/source/fogplay_nx`), а команды выполняйте в Bash.

Нужны:

- C++17, Bash, Git, Python 3, CMake >= 3.16, make, pkg-config, tar, patch и binutils;
- devkitPro с devkitA64, libnx и инструментами `elf2nro`, `nacptool`;
- Switch portlibs: curl, SDL2, SDL2_image, SDL2_ttf, Opus, FFmpeg 7.1 с **NVTEGRA/Horizon** и их статические зависимости;
- интернет для первоначального получения закреплённых исходников RTC и FFmpeg.

Установка devkitPro описана в [официальной инструкции Switchbrew](https://switchbrew.org/wiki/Setting_up_Development_Environment). Официальный [образ devkitpro/devkita64](https://github.com/devkitPro/docker/blob/master/devkita64/Dockerfile) устанавливает группы `switch-dev` и `switch-portlibs`.

Проверенное окружение: devkitA64 r29.2 (GCC 15.2.0), libnx 4.12.0, SDL2 2.28.5, SDL2_image 2.0.4, SDL2_ttf 2.22.0 и switch-ffmpeg 7.1. Скрипт FFmpeg требует **libavcodec 61.19.100**, NVTEGRA и совпадение заголовков с закреплённым исходником; новая произвольная версия FFmpeg не является заменой. Linux-пакеты `libavcodec-dev` нужны только для локальных тестов, не для Switch-сборки.

Для обычных инструментов и локальных тестов в Ubuntu:

```sh
sudo apt install build-essential git cmake pkg-config python3 patch tar xz-utils \
    libcurl4-openssl-dev libsdl2-dev libsdl2-image-dev libsdl2-ttf-dev \
    libavcodec-dev libavutil-dev libswscale-dev libopus-dev libwebp-dev ffmpeg fonts-dejavu-core
```

## Компиляция

Из корня проекта:

```sh
export DEVKITPRO=/opt/devkitpro
export DEVKITA64="$DEVKITPRO/devkitA64"
JOBS=4 bash build.sh
python3 package.py
```

`build.sh` получает libdatachannel v0.24.1 и Mbed TLS 3.6.4 с закреплёнными ревизиями, применяет Switch-патчи и собирает их в локальный `third_party/rtc/switch`. Затем создаёт диагностическую версию объекта декодера FFmpeg в `third_party/ffmpeg-diag`, не изменяя установленный devkitPro. Первый запуск существенно дольше повторной сборки.

Результат:

- `dist/fogplay_nx.nro` — приложение;
- `dist/fogplay_nx.elf` — символы для диагностики;
- `dist/fogplay_nx-sd.zip` — архив для SD;
- `dist/verification.json` — версия, контрольные суммы и структурные проверки пакета.

`romfs/cacert.pem`, `romfs/ui/` и `assets/icon.jpg` включаются в приложение. Брендинг уже подготовлен; для его изменения исходные PNG и редактируемые SVG находятся в `assets/branding/`. Дополнительные зависимости конвертера: `potrace`, Pillow, CairoSVG.

## Проверки

```sh
bash tools/test/all.sh
# Дополнительно: многократное создание/очистка RTC, отказ инициализации и TLS
bash tools/test/all.sh --extended-rtc
```

Проверяются каталог, авторизация, хранение, аренда и её завершение, управление, обложки, видеопоток и локальный WebRTC. Платные аренды этим набором не создаются. Тесты медиадекодирования требуют host FFmpeg с libx264/libx265. Первый RTC-тест собирает host-зависимости. Проверки на ПК и успешная компиляция не заменяют запуск на физической консоли.

Отдельные группы можно запускать через `bash tools/test/host.sh`, `bash tools/test/stream.sh`, `bash tools/test/steam-artwork.sh` и остальные скрипты в той же папке.

## Структура

Код организован по функциям приложения (feature-first), внутри которых разделены правила, сценарии, внешние адаптеры и представление:

```text
src/
  main.cpp          # точка входа
  app/              # сборка приложения и общий координатор интерфейса
  platform/switch/  # libnx, SDL, жизненный цикл системных служб
  core/             # HTTP, хранение, журналы
  features/
    auth/           # вход и сохранение авторизации
    catalog/        # каталог, обложки, недавние игры, задержка
    playstation/    # подборка ПК и PlayStation-управление
    session/        # оформление, восстановление и остановка аренды
    streaming/      # протокол, видео, звук, управление
    settings/       # изображение и раскладка
```

Доменные правила не зависят от SDL/libnx. Сценарии аренды работают через `RentalService`; реализация `Api` подключается при сборке приложения. Потоковые и графические адаптеры изолированы от этих правил. Общий координатор представления сохраняет последовательное владение состоянием и сетевым заданием; детали — в [ARCHITECTURE.md](docs/ARCHITECTURE.md).

Рабочие сборки, кэш зависимостей, журналы и данные аккаунта исключены через `.gitignore`. История исследований и старые инструкции выпусков не входят в исходники.

## PlayStation через Fog Play

Раздел с иконкой PlayStation показывает семь ПК по четыре в строке: `3A7X47`, `3A7X49`, `3A7X48` (MamkinZabiyaka), `F4BX8` (Karahun), `61EFX15`, `61EFX4`, `61EFX3` (CrazyGames). «Онлайн» означает, что ПК найден в актуальной выдаче МТС; «Офлайн» — не найден после загрузки всех страниц. При ошибке или неполной загрузке для ненайденных ПК отображается «Статус неизвестен». Это признак наличия в каталоге, а не гарантия свободной аренды. Список обновляется при открытии раздела и кнопкой X. Цены и тарифы загружаются с промостраниц МТС и повторно проверяются перед заказом; отсутствующий или некорректный тариф блокирует запуск.

При запуске из этого раздела клиент передаёт штатный режим Fog Play `isPS`. Это управление через удалённый ПК, а не прямое подключение Switch к PS5. Раскладка физических кнопок в трансляции: **B → крест, A → круг, Y → квадрат, X → треугольник**; настройка Xbox-раскладки продолжает действовать в интерфейсе приложения. `+` передаёт Options, `−` — Share/Create. **L + R + −** передаёт кнопку PS, короткий тап по экрану — нажатие тачпада. Свайп передаётся как движение пальца по тачпаду (до двух контактов); гироскоп и акселерометр передаются отдельными командами Fog Play. **− + +** открывает меню трансляции, как раньше.

Передача тачпада и датчиков экспериментальная: формат `gamepad_touch` / `gamepad_sensor` подтверждён обработчиками Windows-хоста Fog Play 0.0.0.184. Используется виртуальный DS4; это не полная эмуляция DualSense. Поддержку версии конкретного удалённого ПК нужно проверить на консоли. Адаптивные триггеры и полная отдача DualSense не реализованы.

В 0.5.5 строки `PS input`, `PS sensors`, `PS native queued` и `PS transport input` в журнале разделяют чтение касаний/свайпов и датчиков, постановку в очередь, отправку и ошибки. Успешная отправка в RTC не является подтверждением реакции игры (`ack=unavailable`). В меню трансляции, при восстановлении и выходе контакты отпускаются, движение нейтрализуется; ввод интерфейса не передаётся в игру. Исходные и преобразованные оси датчиков записываются с единицами для проверки направления на устройстве.

Короткий тап: не более 250 мс, движение не более 12 пикселей экрана; нажатие кнопки тачпада удерживается 80 мс. Более длинное касание остаётся контактом тачпада. Мышь и правый стик движениями консоли не подменяются.
